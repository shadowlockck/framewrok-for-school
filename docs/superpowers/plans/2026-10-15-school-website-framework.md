# План реалізації: Фреймворк для створення сайтів українських шкіл (School Website Framework)

> **Дата створення:** 2026-10-15  
> **Статус:** Затверджено до реалізації  
> **Стек технологій:** Django (Python), Django REST Framework, MySQL, React, TypeScript, Tailwind CSS, Docker.  
> **Цільова аудиторія:** Розробники, які створюють та підтримують сайти закладів загальної середньої освіти (ЗЗСО).

---

## 1. Загальний огляд та мета проекту

Мета — розробити повнофункціональний, розширюваний open-source веб-фреймворк для розгортання офіційних сайтів українських шкіл із повною відповідністю нормативно-правовим актам:
- **Стаття 30 Закону України «Про освіту»** («Прозорість та інформаційна відкритість закладу освіти»);
- **Статті 30, 39, 45, 46, 50 Закону України «Про повну загальну середню освіту»**;
- **Порядок зарахування, відрахування та переведення учнів** до державних та комунальних закладів освіти;
- **Закон України «Про захист персональних даних»** (захист списків зарахованих учнів);
- **Стандарти цифрової доступності WCAG 2.1 AA** (версія для людей з порушенням зору, контрастність, семантика).

---

## 2. Архітектурні рішення (згідно з погодженими вимогами)

1. **Архітектурна модель:**
   - **Backend:** Django 5.x + Django REST Framework + MySQL 8.x.
   - **Frontend:** React 19 + TypeScript + Tailwind CSS (SPA з адаптивною версткою та підтримкою WCAG).
   - **CMS:** Кастомізований Django Admin із зручними віджетами, фільтрами та валідацією обов'язкових полів.
2. **Модель розгортання:** Окремий незалежний екземпляр (Single-tenant) для кожної школи через Docker Compose.
3. **Система тем:** Динамічні CSS-змінні (Tailwind Themes) — школа налаштовує власні кольори, шрифти, логотип через адмінку або простий конфігураційний файл.
4. **Багатомовність:** Українська (за замовчуванням) та Англійська (Django i18n + React i18next).
5. **Рольова модель:**
   - `SuperAdmin` — технічний адміністратор школи;
   - `ContentAdmin` — відповідальний за сайт / документообіг (педагог/секретар з надбавкою 10%);
   - `Teacher` — публікація матеріалів, розкладу, оголошень;
   - `Parent` / `Student` — доступ до кабінету / персоналізованого контенту (за потреби).
6. **Автоматизація строків оприлюднення:**
   - Планувальник публікації (Scheduled Publishing) з перевіркою строків (наприклад, обов'язкове оприлюднення кошторису/фінансових звітів протягом 10 робочих днів з дня затвердження).
7. **Модульність:** Модульна архітектура Django Apps (`school_core`, `school_legal`, `school_admissions`, `school_nutrition`, `school_news`, `school_schedule`, `school_gallery`).

## 4. Поетапний план реалізації

### Етап 1: Ініціалізація інфраструктури та Docker
- [ ] Створити `docker-compose.yml` (сервіси: `mysql`, `backend`, `frontend`, `nginx`).
- [ ] Налаштувати конфігураційні змінні оточення (`.env.example`).
- [ ] Налаштувати скрипти міграцій та створення суперкористувача.

### Етап 2: Backend — Core та Legal (ст. 30 ЗУ «Про освіту»)
- [ ] **Додаток `core`**:
  - Модель `SchoolProfile` (назва, ЄДРПОУ, засновник, контактні дані, мова освітнього процесу, ліцензований обсяг та факт учнів).
  - Модель `ThemeSettings` (первинні та вторинні кольори, шрифти, логотип).
- [ ] **Додаток `legal`**:
  - `Document` (статут, ліцензії, сертифікати акредитації, освітні програми, річний звіт, результати аудиту).
  - `StaffMember` (кадровий склад згідно ліцензійних умов, керівництво, педрада).
  - `FinancialReport` (кошториси, надходження публічних коштів, благодійна допомога, дати затвердження та оприлюднення).
  - `ManagementBody` (структура та органи управління, загальні збори колективу).
  - `DirectorVacancy` (конкурс на посаду керівника за ст. 39: строк, вимоги, комісія).

### Етап 3: Backend — Admissions (Зарахування, території, інклюзія)
- [ ] **Додаток `admissions`**:
  - `ServiceTerritory` (територія обслуговування: перелік вулиць/будинків, прив'язка до карти).
  - `AdmissionRule` & `EducationForm` (очна, дистанційна, екстернат, сімейна, педпатронаж).
  - `ClassCapacity` (паралелі, кількість учнів у кожному класі, наявність вільних місць).
  - `AdmissionLottery` & `EnrolledStudent` (жеребкування, публікація списків зарахованих — виключно прізвища без персональних даних).
  - `InclusionCondition` (умови доступності для дітей з ООП).

### Етап 4: Backend — Безпека, Булінг та Харчування
- [ ] **Додаток `nutrition`**:
  - `DailyMenu` (щоденне меню за віковими групами: 1-4, 5-9, 10-11 класи).
  - `CateringProvider` (постачальник послуг харчування).
- [ ] **Додаток `safety`**:
  - `AntiBullyingPlan` (план заходів, порядок подання та розгляду заяв, правила поведінки).
  - Форма конфіденційного подання заяви про булінг (з дотриманням ЗУ «Про захист персональних даних»).

### Етап 5: Backend — Модулі (Новини, Розклад, Галерея)
- [ ] Додаток `news` (категорії, новини, анонси, важливі сповіщення).
- [ ] Додаток `schedule` (розклад уроків, розклад дзвінків, графік чергувань).
- [ ] Додаток `gallery` (альбоми подій, фотозвіти).

### Етап 6: Frontend — Дизайн-система, WCAG та Публічні Сторінки
- [ ] Налаштувати Tailwind CSS з підтримкою тем (CSS-змінні).
- [ ] Реалізувати компонент `AccessibilityPanel` (збільшення шрифту, зміна контрасту: чорно-білий, жовто-чорний, інтервали).
- [ ] Розробити обов'язкові сторінки за ст. 30:
  - «Прозорість та інформаційна відкритість» (єдиний навігаційний реєстр обов'язкових документів);
  - «Вступ до школи / Зарахування» (вільні місця, територія, правила);
  - «Фінансова звітність та кошторис»;
  - «Харчування та меню»;
  - «Безпека та протидія булінгу».
- [ ] Двомовний перемикач (UK / EN).

### Етап 7: Документація, тестування та інструкції з оновлення
- [ ] Написати юніт-тести та API-тести для перевірки доступу та безпеки даних.
- [ ] Скласти керівництво з розгортання та скрипти автоматичного оновлення (`deploy.sh`, `backup.sh`).
