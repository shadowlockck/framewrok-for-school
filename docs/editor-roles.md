# Редакторські ролі сайту школи

Після встановлення пакета та вибору модулів застосуйте міграції й налаштуйте групи:

```bash
python manage.py migrate
python manage.py setup_school_roles --dry-run
python manage.py setup_school_roles
python manage.py createsuperuser
```

Технічний адміністратор створює працівника в `/admin/`, задає пароль, вмикає
`is_active` та `is_staff`, призначає одну або кілька груп із префіксом
«Шкільний фреймворк: ». Прапорець `is_superuser` працівнику не потрібен.
Редактор сам публікує матеріали у дозволеному розділі. Усі записи цього розділу
спільні для його редакторів.

| Група | Доступ |
| --- | --- |
| Головний редактор | Увесь публічний вміст активних модулів, перегляд і зміна профілю школи та теми. |
| Редактор новин | Категорії, новини, публікація та зняття з публікації. |
| Редактор документів і відомостей | Документи, категорії, кадри, вакансії. |
| Редактор фінансової звітності | Фінансові звіти. |
| Редактор вступу | Території, класи, списки зарахованих і жеребкування. |
| Редактор харчування | Постачальники й меню. |
| Редактор розкладу | Розклад уроків і дзвінків; перегляд класів для вибору. |
| Редактор галереї | Альбоми й фотографії. |
| Редактор публічного розділу безпеки | Політики протидії булінгу. |
| Відповідальний за конфіденційні звернення | Перегляд звернень, зміна статусу опрацювання та службових приміток. |

Редактори розділів мають стандартні права Django `view`, `add`, `change`, `delete`
на перелічені моделі. Головний редактор не отримує доступу до конфіденційних
звернень і не керує користувачами. Відповідальний за звернення не може створювати
чи видаляти їх через адмінку й не змінює початковий текст та контакт заявника.
Для редагування профілю школи головний редактор отримує тільки `view/change`;
профіль і тему створює технічний адміністратор.

Для відкликання доступу приберіть групу з користувача. Перевірте його інші групи
та індивідуальні permissions: Django об'єднує ці права. Для повного блокування
вимкніть `is_active`.

Після зміни модулів чи оновлення пакета повторіть `migrate`, перегляньте
`setup_school_roles --dry-run` та виконайте `setup_school_roles`. Команда керує
лише групами з префіксом фреймворку. Зайві дозволи в цих групах вона прибирає,
а групи та членство вимкнених модулів зберігає. Власні групи з іншими назвами
не змінюються. Ролі не призначаються працівникам автоматично.

Для раніше створеного сайту оновлення пакета не переписує його локальні файли.
Застосуйте міграції, запустіть команду ролей у самому сайті й перевірте доступ
співробітників. Нові моделі, які сайт додає самостійно, потребують власних груп
або permissions; готові ролі охоплюють лише моделі фреймворку.
